# UInt32 extraction implementation plan

**Goal:** Generate pure Go for ordinary Lean UInt32 literals, arithmetic and
comparisons with exact unsigned semantics and bounded immutable results.

**Architecture:** Extend the existing typed module IR with a version-gated value
union and fixed primitive catalog. The pinned Lean adapter audits the primitive
source boundary and exports pure-mono leaves. Existing direct Go control emission
allocates each numeric/Boolean result through the same budgeted node constructor.

**Tech stack:** Lean 4.35.0 at the existing commit pin, Go 1.27.4, Python 3.15 and
uv; standard libraries only. Execute with subagent-driven implementation and
independent specification/quality reviews. Numbered steps describe the design;
completion and follow-ups live in the task tracker.

## 1. Add the versioned IR contract

Modify `internal/moduleir/types.go`, `validate.go`, `code.go`; create
`internal/moduleir/primitives.go`. Retain `Schema`/`Profile` for the old module
profile; add `SchemaV3 = "lean-go-ir/v3"` and `ProfileV2 = "pure-module/v2"`.
`validateMetadata` accepts only those exact schema/profile pairs. Keep the JSON
shape unchanged, including non-null args, and independently validate constructed
Programs as before.

Use an immutable fixed registry with lookup returning copies of signatures:

```go
type Primitive struct {
    Name string `json:"name"`
    Params []string `json:"params"`
    Result string `json:"result"`
    Semantics string `json:"semantics"`
}
```

Register exactly the seven declarations in the design. Literal validation uses
`strconv.ParseUint(name, 10, 32)` and requires
`strconv.FormatUint(n, 10) == name`, with length at most ten before parsing.
New value kinds fail under the old profile. Validate canonical Bool for v3 and
preserve lexical/call/type closure checks. Add focused tests before implementation
for every malformed literal, unknown primitive, wrong argument/result, counterfeit
Bool, and cross-profile operation. Run `CGO_ENABLED=0 go test ./internal/moduleir`.

## 2. Emit budgeted numeric operations

Modify `internal/modulegen/emit.go`; extract primitive-expression emission into
`internal/modulegen/primitives.go` if useful. Switch explicitly on value kind.
Use the existing allocation function:

```go
value, err := b.make(0, 0, nil)
if err != nil { return nil, err }
value.scalar = left.scalar + right.scalar
```

Subtraction and multiplication use the corresponding typed uint32 operator.
Shift-left uses `left.scalar << (right.scalar & 31)`. Comparisons select canonical
Bool tags and call the same allocator. Assign scalar fields only before a fresh
node enters any published slot. Literal emission uses validated decimal constants.
The runtime template need not change. Derive the sorted exact used primitive
catalog from validated code and include it in v3 manifests only.

Extend `internal/modulegen/emit_test.go` to compile isolated generated packages:
test boundary arithmetic, all comparison branches, shifts0/31/32/33/max, repeated
execution, immutability, allocation/step failures with invalid output, and a typed
primitive mutation that fails a semantic assertion rather than compilation. Run
`CGO_ENABLED=0 go test ./internal/modulegen` and `go vet` for the affected packages.

## 3. Audit and export numeric Lean leaves

Create `producer/LeanGo/Module/Primitives.lean`. Modify `Audit.lean` and
`Export.lean` to use the exact pinned source/support catalog. Check each allowed
extern symbol, implementation attributes, defining module and axiom set; reject
all other leaves. Cover source overloaded operator wrappers and fixed UInt32
instances without admitting arbitrary Nat or Std runtime computation.

In encoding, recognize `.lit (.uint32 value)` and emit the canonical decimal
literal object. For a constant application, recognize a catalog primitive before
ordinary function traversal. Check its pure-mono declaration signature/safety
and saturated argument variables, then emit a primitive value and omit it from
the user function worklist. Collect Bool in the type closure for comparisons.
Preserve compile-time and final-state audit checks for support declarations too.

Add producer regressions under `scripts/test_numeric_admission.py`: every basic
operator/literal; `a*2` optimized shift; source UInt32 wraparound literals; custom
UInt32 operator instances; wrong/late extern attributes on primitive names;
local/scoped/late CSimp on primitive/support wrappers; unsupported division,
other integer widths and unknown native functions. Assert failed extraction
preserves the previous output and fails at the intended boundary, not Lean syntax.

## 4. Connect producer identity and schema dispatch

Update `scripts/export_module.py` producer input list with `Primitives.lean` and
emit v3/pure-module/v2 metadata for fresh module exports. Extend freshness checks
in `scripts/generate.py` for both module schemas. Add v3 dispatch to
`cmd/lean-go/main.go` and tests, keeping audited-v1 handling untouched.
Adjust relevant Python fixtures and prior negative arithmetic fixture to an
operation still unsupported (division), and retain an explicit old-profile
numeric-IR rejection test. Use uv for every Python invocation.

## 5. Add examples and native differential tests

Create `examples/modules/Numbers.lean` with one result ADT bundling the seven
operations and literal/optimized-expression cases. Create
`examples/reference/NumbersReference.lean` with a bounded test-only JSON codec
for input pairs and native results. Generate `generated/numbers/` and
`testdata/numbers.ir.json` through the actual pipeline. Update existing module
artifacts through regeneration as producer/generator identities change; retain
the audited normalizer's unchanged sources/artifacts.

Create `integration/numbers_test.go`. Compare Go output with separately compiled
native Lean for a boundary Cartesian set and deterministic seeded inputs. Check

power-of-two lowering, scalar roots, and a Go-only consumer with `CGO_ENABLED=0`,
Go-only PATH and network module resolution disabled. Compare repeated fresh
producer bytes and tracked fixtures, including manifest primitive catalogs.
