# UInt64 Implementation Plan

**Goal:** Extract exact UInt64 computation into the raw and typed pure-Go APIs.

**Architecture:** Extend the pinned numeric leaf table and add IR v6/profile v4.
Use distinct scalar storage and profile-conditional runtime/API generation while
reusing source audits, record/helper evidence, execution and all resource budgets.

**Tech Stack:** Lean 4.35.0, Go 1.27.4 with CGO disabled, Python 3.15 through uv.

Owned implementation tasks can proceed concurrently within this increment;
specification and quality review follow integration. The task tracker owns status.

## 1. Admit UInt64 source and exact IR

Modify `producer/LeanGo/Module/Primitives.lean`: add an operand-type field to
`NumericPrimitive` (UInt32 default), the seven exact UInt64 leaves, UInt64 literal
and operator wrappers, and its pinned order package. Validate each actual mono
signature against its operand/result descriptor. Extend expected literal externs
and axiom sets by exact names only. Retain full pristine closure observations.

Update `Audit.lean`'s exact compiler support leaf, `Records.lean`'s scalar type and
wrapper cases, and `LocalSource.lean`'s full source closure. In `Export.lean`, skip
both scalar widths when exporting ADTs, encode `.lit (.uint64 n)` as kind
`uint64` with `toString n.toNat`, and derive primitive arguments from the descriptor.

Advance `scripts/export_module.py` to v6/profile v4 and teach `scripts/generate.py`
its freshness schema. Add `scripts/test_uint64_admission.py` using the existing
fresh-source harness by composition. Test real emitted wide helpers, mixed-width
records, literal values above 2^53/maxUInt64, primitive and historical support
mutations, erased division/remainder, source imports and custom operator behavior.
Update existing unsupported-width and current-producer schema assertions; retain
legacy IR fixtures as legacy tests.

Observe initial rejection of a valid UInt64 root, then run:

```sh
LEAN_GO_MODULES=1 uv run --locked python -m unittest discover -s scripts -p 'test_uint64_admission.py'
```

## 2. Validate and generate the new numeric profile

Modify `internal/moduleir/types.go`, `validate.go`, `code.go`, `primitives.go`,
`api.go` and `decode.go`. Add SchemaV6 and ProfileV4; keep strict older combinations.
The new profile enables both UInt32 and UInt64, joins and API metadata. A UInt64
literal uses `strconv.ParseUint(text, 10, 64)` and must round-trip exactly. Primitive
signatures use the selected width, including Bool comparison results. A legacy
ordinary type named UInt64 must not silently acquire new scalar behavior.

Add focused `internal/moduleir/uint64_test.go` for maximum and overflowing literals,
leading zeros/signs, mixed-width substitutions, legacy rejection and API/profile
combinations. Update CLI schema dispatch and add a v6 CLI regression.

In `internal/modulegen`, extend the scalar/type mapping, schema emission and numeric
expressions. Keep UInt32 ID zero and storage unchanged; assign UInt64 a distinct
nonnegative ID after ADTs. Render the new runtime fields/accessor only for v6,
using focused conditional templates rather than duplicating the complete runtime.
Require inactive scalar payloads to be zero at import. Preserve legacy rendering.

Extend the facade scalar descriptor with native `uint64` conversion/read helpers,
including nullary scalar roots and mixed records. Advance generator/manifest
versions while preserving existing profile semantics. Add
`internal/modulegen/uint64_test.go` with executable generated tests and the existing
`runGenerated` harness. Compare raw and typed results, full-width values, shifts,
inactive payloads, mismatched widths, zero results on errors and resource limits.

Run `CGO_ENABLED=0 GOTOOLCHAIN=local go test ./internal/moduleir ./internal/modulegen ./cmd/lean-go`.

## 3. Add wide examples and native differential tests

Create `examples/modules/Wide.lean` with a typed result record covering the seven
operations, wrapped/max/above-2^53 literals and a mixed computation. Include
separate source roots or fresh test modules for mixed-width records and surviving
captured/reduced helpers as needed; do not accidentally test only inlined helpers.

Create `examples/reference/WideReference.lean` with strict bounded input parsing,
twenty-digit UInt64 bounds and exact output. Add `integration/uint64_test.go` using
the existing toolchain/consumer helpers. Its independent oracle uses `math/big`,
reduces arithmetic modulo 2^64, and masks shifts modulo 64. Include seeded inputs
and boundary combinations, direct uint64 JSON decoding, malformed/oversized wires,
typed getters and an isolated Go-only consumer.

Generate `generated/wide/` and `testdata/wide.ir.json` using fresh paths and
regenerate the seven existing ordinary modules. Preserve the audited normalizer.
Compare old module semantic IR after removing only new schema/profile/input
identities; report intentional representation changes instead of claiming byte
identity for a profile that now supports another scalar width.
