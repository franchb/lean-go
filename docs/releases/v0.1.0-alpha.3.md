# v0.1.0-alpha.3 — release candidate

**Status: unpublished candidate.** The current published preview is
[`v0.1.0-alpha.2`](v0.1.0-alpha.2.md). Do not use `go get ...@v0.1.0-alpha.3`
until that tag has been published. Follow the
[candidate walkthrough](../release-candidate.md) to evaluate this checkout and
record its exact commit.

This candidate brings together the work completed since alpha.2:

- **Multi-root extraction:** repeat `--root` to share generated types,
  constructors and runtime across two to 64 selected functions. Typed callers use
  named entrypoints; raw callers use `RunRoot`. Single-root APIs remain available.
- **Bounded quota library:** immutable `UInt64` accounting with create, reserve,
  release and remaining-capacity operations, an ergonomic Go API and ten Lean
  source theorems covering guards, preserved bounds, rejection identity and exact
  arithmetic.
- **Reusable proof contracts:** a strict project JSON contract maps theorems to
  separately authored expected propositions. Fresh pinned Lean builds verify
  exact types and foundational axioms, and deterministic evidence records source,
  checker and generated-package hashes. Both single-root and multi-root packages
  are supported.
- **Generated-program differential testing:** seeded source programs are compared
  with an independent model, native Lean and both Go APIs, with replayable evidence
  and bounded failure reduction.

Read [multi-root extraction](../research/extraction-multiroot.md),
[quota](../quota.md), [proof contracts](../proof-contracts.md) and
[differential testing](../research/differential-testing.md) for their contracts
and limits. The Apache 2.0 license is unchanged.

## Toolchains and compatibility

Consumers use Go 1.27.4 and `CGO_ENABLED=0`. They do not need Lean, Python, uv or
a C compiler. Regeneration and proof checking use pinned Lean 4.35.0 and Python
3.15 through `uv`; the Python tools still have no third-party dependencies.

Single-root module exports retain v6 IR/profile v4 and `Run`/`RunTyped`. Multi-root
exports use v7 IR/profile v5 and named entrypoints, without a default root. Earlier
supported IR/profile versions retain their existing behavior. Quota's existing
command remains available; its evidence now uses the shared
`lean-go-proof-evidence/v1` schema.

The supported runtime subset remains pure, first-order and monomorphic, including
enums, recursive sums, self recursion, records/updates, local joins, audited
compiler helpers and UInt32/UInt64 arithmetic/comparisons. External Lake packages,
general polymorphism/collections, escaping closures, mutual function recursion,
effects, numeric conversions, division/remainder and unrecognized compiler forms
remain unsupported. APIs are experimental.

## Assurance boundary

Lean checks the selected source propositions; reviewers decide whether those
propositions capture the intended requirements. The permitted axiom dependencies
are fixed to `propext`, `Classical.choice` and `Quot.sound`. Admitted proofs,
custom axioms and compiler-trust proof shortcuts are rejected.

The Lean compiler, extractor, Go emitter/runtime and Go compiler remain tested and
trusted. This is not a formally verified compiler. Source elaboration, including
macros and initializers, is trusted; workspace integrity checks are not a sandbox
for hostile compile-time code. Evidence hashes provide traceability, not an
independent authenticity guarantee.

## Release validation

Branch CI exercises the candidate-version Go-only consumer on Linux and Windows.
It resolves a temporary local module-proxy artifact from the checkout at the
proposed version, verifies the selected module without replacements, and executes
tree, UInt64, quota and multi-root checks offline. This does not claim the public
alpha.3 tag is available or establish the checksum of a future published archive.

The Linux extraction job runs source proofs, native comparisons, fresh generation,
source-admission and differential suites, plus the clean-checkout proof-to-Go
walkthrough. Candidate receipts are attached to the corresponding CI run.

After publication, the tagged consumer path downloads the exact public version
through the Go proxy/checksum database and repeats the same Go-only API checks.
Those results must be recorded separately from prepublication candidate evidence.
