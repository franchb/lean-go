# v0.1.0-alpha.7 — experimental preview candidate

This checkout prepares alpha.7, Python package `0.1.0a7`. The commands below
apply after `v0.1.0-alpha.7` is published. Before publication, install the CLI
from this same [checkout](../cli.md#development-checkout) and run the
[local candidate checks](../release-candidate.md). Those checks do not establish
public tag availability or the checksum of a published module archive.

```sh
uv tool install --python 3.15 "git+https://github.com/franchb/lean-go.git@v0.1.0-alpha.7"
lean-go --version
lean-go doctor
```

Go library consumers can pin the same release after publication:

```sh
go get github.com/franchb/lean-go@v0.1.0-alpha.7
```

## Changes since alpha.6

- **Two exact width conversions:** `UInt32.toUInt64` preserves the value by
  zero extension; `UInt64.toUInt32` keeps the value modulo 2^32. These are the
  only newly admitted conversion leaves. Their signatures, extern identities,
  logical dependency closures and source history remain audited. See the
  [width-conversion report](../research/extraction-width-conversions.md).
- **Ordinary left-shift notation:** `<<<` works for `UInt32` and `UInt64` through
  five exact audited source wrappers: `HShiftLeft.hShiftLeft`,
  `instHShiftLeftOfShiftLeft`, `ShiftLeft.shiftLeft`, `instShiftLeftUInt32` and
  `instShiftLeftUInt64`. It lowers to the existing `UInt32.shiftLeft` and
  `UInt64.shiftLeft` leaves; there is no new shift primitive. Counts remain
  masked modulo 32 or 64, and left shift alone retains the earlier schema.
- **Standalone proved Words module:** the [copyable example](../../examples/proofs/words)
  exposes five roots for widening, narrowing, packing, high-word extraction and
  low-word extraction. Seven universally quantified Lean source claims cover
  value preservation, modulo narrowing, both conversion round trips and the
  packing/unpacking identities. Independent typed/raw Go tests check the five
  operations and seven laws over 699 boundary and seeded triples, plus budgets,
  failure results and ownership. The copied module deploys with Go alone.

The compatibility corpus contains 13 cases: seven accepted cases and six
expected rejections. The additions cover ordinary left shift at both widths
with direct-call controls, and width conversions with packing/unpacking.
Independent Go consumers check their arithmetic. Genuine build failures remain
distinct from source-admission rejections. The
[compatibility harness](../compiler-compatibility.md) is checkout research
tooling, separate from the installed CLI and wheel.

The normalizer, typed APIs, multi-root extraction, quota, reusable proof
contracts, bitwise operations and frame-storage reuse remain available. The
three standalone demos are clamp (three source claims, 681 finite Go input
pairs), flags (eight claims, 4,752 pairs) and Words (seven claims, 699 triples).
The separate [release walkthrough](../release-candidate.md) checks three fresh
clamp claims and a 177-case isolated Go consumer.

Earlier v2–v9 schemas retain their primitive restrictions and reject the new
conversion leaves. Single-root packages keep `Run` / `RunTyped`; multi-root

The generator identity and producer hashes changed since alpha.6. Regenerate

Generation preserves and rejects differing existing package bytes. Pair all
three tagged examples with the CLI from that same tag; candidate or development
artifacts require the CLI from the same checkout, including its local changes.
The alpha.7 preparation changes only release metadata and documentation; the
already qualified generated artifacts and proof evidence remain unchanged.

Packaging still uses Hatchling **1.33.0**. Runtime Python code has no third-party
dependencies; generated consumers need only Go and generated sources with
`CGO_ENABLED=0`.

## Scope and assurance

Runtime division/remainder, further width conversions, other numeric types,
broad generic collections, polymorphism, escaping closures, effects, mutual
function recursion, external Lake packages and unsupported compiler forms
remain deferred or excluded. Words is numeric word packing, with no byte-order
or serialization contract. Its remainder and bit-vector proof helpers do not
become runtime primitives. APIs and supported compiler forms are experimental.

Lean checks the selected source claims, not an end-to-end compiler-correctness
theorem. Reviewers still judge whether the independently authored expected
propositions capture the requirements. The compiler, extraction adapter, Go
emitter and runtime remain tested and trusted. Finite Go tests and matching
hashes provide regression evidence and traceability, not universal Go proofs
or authenticity. Source elaboration can execute macros and initializers; it is
trusted, not sandboxed. Logical resource budgets can reject an otherwise total
Lean call, so callers must check errors before using results.

## Validation boundaries

The branch workflows are configured to run Go tests and vet on Linux and
Windows; pinned Lean source proofs, native comparisons, regeneration, source
admission and differential tests; and the same-pin 13-case compatibility corpus.
The width-conversion campaign compares five roots over 206 finite triples with
an independent arithmetic model, native Lean, raw Go and typed Go. Left-shift
checks compare ordinary notation and direct calls, including masked counts and
audited source-boundary rejection cases. These are bounded regression gates.

The installed-CLI workflow audits both a direct wheel and a wheel rebuilt from
the source distribution on Linux and Windows. Each installed wheel runs the
177-case external Go consumer and freshly regenerates and checks all three
standalone demos, including their 18 source claims and Go-only deployments.
These workflow descriptions are coverage expectations, not claims that a
future branch or tag run has passed.

The local candidate test serves a synthetic `v0.1.0-alpha.7` module archive
through a temporary proxy. The separate exact-tag Go check downloads the public
release through the Go proxy and checksum database, verifies its version without
a local `replace`, and exercises existing root-module tree, UInt64, quota and
multi-root consumers on Linux and Windows. That public Go consumer does not
cover every bitwise operation or width conversion.

The exact-tag installed-CLI workflow separately installs the public Git tag
with uv, checks its package version and toolchain, and freshly generates and
verifies clamp, flags and Words, including source proofs and Go-only deployments
on Linux and Windows. After publication, the GitHub release record should link
the observed branch and tag workflow results.
