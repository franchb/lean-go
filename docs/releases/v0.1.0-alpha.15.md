# v0.1.0-alpha.15

Generator v18 extracts a named Lean byte fold over a structure with two direct `UInt32` fields. Eligible steps run in a Go loop that carries both words across the borrowed `[]byte`. The public result is an immutable record. Recursion and joins in the step retain bounded execution through the raw executor. Both paths enforce the same seven resource limits. [Adler-32 example](../../examples/proofs/adler32)

## Install

```sh
uv tool install --force --python 3.15 "git+https://github.com/franchb/lean-go.git@v0.1.0-alpha.15"
lean-go --version
lean-go doctor
```

The CLI reports `lean-go 0.1.0a15`. Use Go 1.27.4, `CGO_ENABLED=0`, and Lean 4.36.0 or 4.36.0-rc2. To upgrade from alpha.14, regenerate the Go package, IR, manifest and proof evidence together. [Installation guide](../cli.md)

## Streaming Adler-32

The source contract checks a byte update against natural-number arithmetic modulo 65521 and proves that any partition of a message produces the same two sums. The Go consumer checks the packed checksum against `hash/adler32`. Across eight standalone demos and the checksummed frame, this release checks 58 distinct source claims. [Proof contract](../../examples/proofs/adler32/proof-contract.json)

For a 256-byte block on Linux/amd64 with Go 1.27.4, heap allocations fell from 3,722 to 4 per call and allocated bytes from about 277 KiB to 256 bytes. The allocation regression also compares 1-byte and 1,024-byte inputs. [Benchmark and reproduction command](../research/generated-go-performance.md#two-word-record-folds)
