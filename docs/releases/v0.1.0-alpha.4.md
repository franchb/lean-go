# v0.1.0-alpha.4 — experimental preview

Install the CLI from the public release tag with [uv](https://docs.astral.sh/uv/):

```sh
uv tool install --python 3.15 "git+https://github.com/franchb/lean-go.git@v0.1.0-alpha.4"
lean-go --version
lean-go doctor
```

The Python package version is `0.1.0a4`. Go library consumers can pin the same
release:

```sh
go get github.com/franchb/lean-go@v0.1.0-alpha.4
```

This preview adds the following to [alpha.3](v0.1.0-alpha.3.md):

- **Installable CLI:** `lean-go doctor`, `lean-go generate` and
  `lean-go check-proofs` work from an external project without a neighboring
  repository checkout. The package carries the required producer sources and
  materializes a temporary workspace. Help and version work without producer
  tools; `doctor` checks their exact supported identities. Both wheel and source
  distributions are exercised outside the checkout.
- **Recursive frame-storage reuse:** generated module code reuses retired slot
  backing at a previously visited call depth. In the measured balanced-tree
  typed workload, bytes per operation fell **41.2%**, allocations fell **38.1%**,
  and median runtime fell **8.6%**. These are local, five-sample results for that
  workload, not general speedup claims. Read the [method and limits](../research/generated-go-performance.md)
  and raw [before](../research/data/generated-go-before.txt) and
  [after](../research/data/generated-go-after.txt) data. Numeric and quota
  allocation counts are unchanged.
- **Copyable clamp demo and article:** the [standalone Go module](../../examples/proofs/clamp)
  includes ordinary Lean sources, proof contracts and evidence, generated Go,
  an executable, and independent tests. Three source claims establish boundedness,
  preservation of already-bounded inputs and idempotence. The Go tests exercise
  169 boundary pairs plus 512 seeded full-width pairs: **681 finite model cases**.
  The [article](../articles/lean-proofs-to-go.md) explains how to generate,
  check and deploy it, including the extraction trust boundary.

Follow the [CLI guide](../cli.md) or [release walkthrough](../release-candidate.md)
for reproducible commands. The walkthrough's separate 177-case consumer remains
available alongside the standalone demo's 681-case suite. Multi-root extraction,
the quota library and reusable source-proof contracts remain supported. The
Apache 2.0 license is unchanged.

## Toolchains and compatibility

Producers use Python **3.15**, Go **1.27.4**, and Lean/Lake **4.35.0**. Lean must
report commit `eb6cafb7290e8bd5f2937522d8d804f58f02bafc`; matching only its version
string is insufficient. Packaging uses pinned Hatchling **1.33.0**; runtime Python
code has no third-party dependencies. Consumers need only Go and generated code,
with `CGO_ENABLED=0`; they need no Lean, Python, uv or C compiler.

The module generator identity advances to `lean-go-modulegen/v7`. Regenerated
manifests and proof evidence therefore change, while IR/profile versions, public
APIs and logical resource charges remain unchanged. Single-root exports retain
v6 IR/profile v4 and `Run`/`RunTyped`; multi-root exports retain v7 IR/profile v5
and named entrypoints. Earlier supported IR/profile versions keep their existing
restrictions. Slot storage is reused within one invocation only. `MaxSlots` still
counts cumulative logical entered slots, and `MaxFrames` still limits active
depth; physical Go allocation counts are separate from logical allocation budgets.

The supported runtime subset remains pure, first-order and monomorphic. It
includes enums, recursive sums, self recursion, records and updates, local joins,
audited compiler helpers and UInt32/UInt64 arithmetic and comparisons. General
polymorphism and generic collections remain deferred. External Lake packages,
escaping closures, mutual function recursion, effects, numeric conversions,
division/remainder and unrecognized compiler forms remain unsupported. APIs and
supported compiler forms are experimental.

## Assurance boundary

Lean checks the selected source propositions; reviewers decide whether those
propositions express the intended requirements. The permitted axiom dependencies
remain `propext`, `Classical.choice` and `Quot.sound`. Admitted proofs, custom axioms
and compiler-trust proof shortcuts are rejected.

The Lean compiler, extractor, Go emitter/runtime and Go compiler remain tested
and trusted. Source-proof evidence and finite Go tests do not constitute an
end-to-end proof of the generated program or a formally verified compiler. The
clamp manifest's `program.claims` is empty; its source claims live in separate
proof evidence. Hashes provide traceability, not independent authenticity.

Source elaboration, including macros and initializers, is trusted. Workspace
integrity checks are not a sandbox for hostile compile-time code. Generated Go
calls can return invalid-limit or exhausted-budget errors; the total Lean
function's theorems do not guarantee success for every operational budget.

## Release validation

Publication requires green branch checks for the tagged commit: Go tests and vet
on Linux and Windows; pinned Lean source proofs, native comparisons, fresh
regeneration, source-admission and differential suites; and installed-wheel,
source-distribution and standalone-demo checks on Linux and Windows.

Tag checks download the exact public Go version through the module proxy and
checksum database and exercise Go-only consumers on Linux and Windows. The
installed-CLI workflow also installs the exact public Git tag with `uv`, verifies
its package version, runs `doctor`, regenerates the copied demo, rechecks its
proofs, and runs its Go-only tests and executable on both systems. These checks
are separate from local candidate evidence. The GitHub release record links the
observed branch and tag results after they pass.
