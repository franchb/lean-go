# v0.1.0-alpha.8 — experimental preview candidate

This checkout prepares **alpha.8**, Python package `0.1.0a8`. Before publication,
install the CLI from this same
[checkout](../cli.md#development-checkout) and run the
[local candidate checks](../release-candidate.md). Those checks do not establish
public tag availability or the checksum of a published module archive.

Only after `v0.1.0-alpha.8` is published:

```sh
uv tool install --python 3.15 "git+https://github.com/franchb/lean-go.git@v0.1.0-alpha.8"
lean-go --version
lean-go doctor
```

Go library consumers can pin the same release after publication:

```sh
go get github.com/franchb/lean-go@v0.1.0-alpha.8
```

## Changes since alpha.7

- **Scalar UInt8:** twelve exact operation leaves provide wrapping add/subtract/
  multiply, unsigned equality/order, AND/OR/XOR/complement and logical shifts
  with counts modulo 8. Two additional leaves provide `UInt8.toUInt32` zero
  extension and `UInt32.toUInt8` truncation modulo 256. All fourteen leaves retain
  exact signature, extern, source-closure, safety, axiom and rewrite audits;
  admission does not trust a namespace. Typed Go uses `uint8`; raw APIs validate
  byte payloads and inactive fields. See the [UInt8 report](../research/extraction-uint8.md).
- **A standalone proved byte codec:** the [copyable Bytes module](../../examples/proofs/bytes)
  exports four roots for little-endian and big-endian encoding and decoding of
  a `UInt32` through a concrete four-field `ByteQuad` record. Twelve universal
  source claims cover four inverse laws and eight arithmetic byte positions.
  Independent typed/raw Go tests compare 652 finite cases with `encoding/binary`
  and check ownership, malformed inputs, invalid wrappers and resource errors.
  The [application walkthrough](../articles/proved-byte-codec.md) shows the source,
  independently authored expected propositions, proofs and runnable Go handoff.
- **Four complete demos:** [Clamp](../../examples/proofs/clamp) has three source
  claims and 681 finite Go input pairs; [Flags](../../examples/proofs/flags) has
  eight claims and 4,752 pairs; [Words](../../examples/proofs/words) has seven
  claims and 699 triples; Bytes has twelve claims and 652 cases. Together they
  provide 30 source claims. Each copied module deploys with Go alone.

The compatibility corpus now has 14 cases: eight accepted cases and six required
rejections. Its `bytes` case independently checks arithmetic, comparisons,
bitwise operations, masked shifts and the two byte/word casts. The
[compatibility harness](../compiler-compatibility.md) remains checkout research
tooling, separate from the installed CLI and wheel. It does not relax the
production compiler pin.

The normalizer, typed APIs, multi-root extraction, quota, proof contracts,
UInt32/UInt64 arithmetic, bitwise operations, width conversions and frame-storage
reuse remain available. Published alpha.7 has no UInt8 engine or byte codec.

## Upgrade from alpha.7

Toolchain pins are unchanged: Go **1.27.4**, Python **3.15** through uv and
Lean/Lake **4.36.0-rc2** at exact commit
`b35cb10cf2ced51a2fd1880cfdbf75c71ab7a35a`. A matching Lean version string alone
is insufficient. The CLI selects its pin without changing Elan's global default.
After the tag is published, upgrade with:

```sh
uv tool install --force --python 3.15 "git+https://github.com/franchb/lean-go.git@v0.1.0-alpha.8"
lean-go --version
lean-go doctor
```

All current module exports use `lean-go-modulegen/v10`. Version selection follows
surviving executable types and operations; erased operations and source spelling
alone do not enable a capability:

| Strongest emitted capability | Single-root IR / manifest / profile | Multiple-root IR / manifest / profile |
| --- | --- | --- |
| UInt32/UInt64 arithmetic, comparisons and left shift | v6 / v6 / `pure-module/v4` | v7 / v7 / `pure-module/v5` |
| UInt32/UInt64 bitwise operations | v8 / v8 / `pure-module/v6` | v9 / v9 / `pure-module/v7` |
| UInt32/UInt64 width conversions | v10 / v10 / `pure-module/v8` | v11 / v11 / `pure-module/v9` |
| UInt8 values or UInt8/UInt32 casts | v12 / v12 / `pure-module/v10` | v13 / v13 / `pure-module/v11` |

Earlier schemas retain their restrictions and reject byte types, literals,
primitives and payloads. The four-root byte codec uses v13 IR/manifest and
`pure-module/v11`. Older demos retain their existing IR schemas while their
manifests and evidence use generator v10. Single-root `Run`/`RunTyped`, multi-root
named typed entrypoints/`RunRoot`, ownership and error semantics remain unchanged.
Each byte encoder needs 11 allocations and 12 steps; each decoder needs 13
allocations and 15 steps. Logical budgets may reject an otherwise total Lean call.

Producer/generator hashes changed since alpha.7. Regenerate package/IR artifacts
and source-proof evidence together into fresh output paths, then inspect and test
the results before replacing tracked artifacts. Differing existing package bytes
are rejected and preserved. Pair examples and CLI from the same checkout or tag;
alpha.7's generator v9 cannot reproduce the candidate's v10 artifacts. This
release preparation changes only metadata and documentation; the already
qualified source, generated artifacts and proof evidence remain unchanged.

Packaging still uses Hatchling **1.33.0**. Runtime Python code has no third-party
dependencies; generated consumers need only Go and generated sources with
`CGO_ENABLED=0`.

## Scope and assurance

UInt16, direct UInt8/UInt64 casts, runtime division/remainder, broad generic
collections, polymorphism, escaping closures, effects, mutual function recursion,
external Lake packages and unsupported compiler forms remain deferred or
excluded. Bytes uses a concrete record; its proof-only natural-number and
bit-vector helpers do not become runtime primitives.

Lean checks the selected source claims, not an end-to-end compiler-correctness
theorem or a universal Go-correctness theorem. Reviewers still judge whether the
independent expected propositions capture the requirements. The compiler,
extraction adapter, Go emitter/runtime and Go compiler remain tested and trusted.
Finite tests and matching hashes provide regression evidence and traceability,
not universal proofs or authenticity. Elaboration can execute macros and
initializers: Lean source is trusted, and this workflow is not a sandbox. Check
resource and malformed-input errors before reading results.

## Validation boundaries

Focused UInt8 qualification compares 19 outputs over 353 boundary and seeded
triples across native Lean, raw Go, typed Go and an independent Python arithmetic/
Boolean model. Generated scalar Go tests separately cover 481 boundary and seeded
pairs across all fourteen new leaves. The Bytes demo checks its twelve laws over
652 finite Go cases. These are bounded tests of the trusted pipeline, separate
from its universal Lean source statements; see the [UInt8 report](../research/extraction-uint8.md).

Branch workflows are configured for Go tests/vet on Linux and Windows; pinned
Lean proofs, native comparisons, regeneration, admission and differential tests;
and the same-pin 14-case compatibility corpus. The production compiler remains
exactly Lean 4.36.0-rc2 at the commit above. Qualification with that compiler on
both sides does not establish support for later Lean versions.

The installed-CLI workflow audits a direct wheel and a wheel rebuilt from the
source distribution on Linux and Windows. Each wheel runs the 177-case isolated
consumer and freshly regenerates all four demos, compares exact artifacts,
checks all 30 source claims and exercises Go-only deployments. The separate
[release walkthrough](../release-candidate.md) checks three fresh Clamp claims
and its 177-case consumer. These are coverage expectations, not claims that a
future branch or tag workflow has passed.

The local candidate test serves a synthetic `v0.1.0-alpha.8` archive through a
temporary Go module proxy. It does not establish public tag availability or a
future module checksum. After publication, the exact-tag Go workflow checks the
public version through the Go proxy and checksum database without a local
`replace`, exercising existing root-module tree, UInt64, quota and multi-root
consumers. That public Go consumer alone does not cover every byte operation.
The exact-tag installed-CLI workflow separately installs the public Git tag and
freshly checks all four demos and 30 claims on Linux and Windows. Published
release notes should link the observed branch and tag workflow results.
