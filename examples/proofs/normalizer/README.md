# A copyable Lean-proved three-valued logic normalizer in Go

This directory is a complete Go module. Copy it anywhere, then build and run it
with Go **1.27.4**. It has no external Go dependencies, `replace` directives, or
runtime dependency on the lean-go repository. The checked-in package was generated
from ordinary Lean source through the module extractor. Regenerate it with this
[checkout's CLI](../../../docs/cli.md#development-checkout).

The Lean program is the normalizer from the project's original extraction pilot,
now extracted through the general module pipeline. It pushes negations onto
variables in strong-Kleene three-valued logic and evaluates negated literals.

The assurance is **proved Lean logic with tested, trusted extraction**. The two
source theorems do not constitute an end-to-end proof of the generated Go program.

## Run with Go alone

From this directory:

```sh
CGO_ENABLED=0 GOTOOLCHAIN=local GOWORK=off GOPROXY=off GOSUMDB=off go test -count=1 ./...
CGO_ENABLED=0 GOTOOLCHAIN=local GOWORK=off GOPROXY=off GOSUMDB=off go run .
```

Expected output, with `F`, `U` and `T` for false, unknown and true:

```text
normalize(not (x4294967295 and U)) = (not x4294967295 or U)
normalize(not not F) = F
normalize(not (F or x0)) = (T and not x0)
```

The Go program builds expressions with the generated typed constructors and
calls the generated root directly:

```go
import normalizer "example.com/proved-normalizer/normalizer"

limits := normalizer.DefaultLimits()
x, err := normalizer.NewExprVar(7, limits)
if err != nil {
    return err
}
input, err := normalizer.NewExprNeg(x, limits)
if err != nil {
    return err
}
result, err := normalizer.RunTyped(input, limits)
```

Results are inspected with `AsLit`, `AsVar`, `AsNeg`, `AsConj` and `AsDisj`.
Every call starts fresh logical resource budgets. Invalid limits return
`ErrLimits`; exhausted budgets return `ErrResource`. These operational errors are
outside the total Lean function's theorem statements.

## What is included

| File or directory | Purpose |
| --- | --- |
| `source/Normalizer.lean` | Ordinary Lean implementation |
| `proof/NormalizerContract.lean` | Independently stated semantics and expected propositions |
| `proof/NormalizerProofs.lean` | Proofs of evaluation preservation and normal form |
| `proof-contract.json` | Selected root and theorem-to-expectation mappings |
| `normalizer/` | Generated Go package and source/output manifest |
| `normalizer.ir.json` | Producer IR with source and compiler provenance |
| `proof-evidence.json` | Freshly checked source proof evidence bound to generated bytes |
| `main.go`, `main_test.go`, `go.mod` | Standalone consumer, independent checks and local module |

The contract restates the strong-Kleene truth tables, an evaluator and the
normal-form predicate without using the runtime's `Tri.neg`. For every
expression `e` and valuation `rho : UInt32 → Tri`, the source claims establish:

1. `eval rho (Normalizer.normalize e) = eval rho e`.
2. `IsNormalForm (Normalizer.normalize e)`: negation appears only directly on
   variables.

Both claims depend only on the `propext` axiom. The Go tests compare the
generated result with an independent Go normalizer and check both properties
under all nine valuations of two variables for all 7,265 expressions up to depth
two, 512 seeded deeper expressions and a chain of 1,001 negations. They also
check invalid limits, budget exhaustion, zero values and the exact executable
output. These finite tests exercise the extraction boundary; they are not proofs
for all Go executions.

## Regenerate and check proofs

With the CLI installed from the same checkout, run from this directory:

```sh
lean-go doctor
lean-go generate --source-dir source --module Normalizer --root Normalizer.normalize --out normalizer --ir-output normalizer.ir.json
lean-go check-proofs --contract proof-contract.json --manifest normalizer/manifest.json --output proof-evidence.json
lean-go check-proofs --contract proof-contract.json --manifest normalizer/manifest.json --evidence proof-evidence.json
```

The generator accepts identical existing output and refuses differing package
bytes; use fresh candidate paths after changing source or tools. Never edit
generated Go by hand.

## Verify the complete handoff

From the lean-go checkout used to install the development CLI:

```sh
normalizer_cli=$(command -v lean-go)
uv run --locked python scripts/check_normalizer_demo.py --cli "$normalizer_cli"
```

The verifier copies this directory into a fresh temporary project, regenerates
every artifact with the installed CLI, compares the bytes, rechecks both proofs,
and runs the copied tests and executable with Go alone.
