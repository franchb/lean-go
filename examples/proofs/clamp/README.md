# A copyable Lean-proved clamp in Go

This directory is a complete Go module. Copy it anywhere, then build and run it
with Go **1.27.4**. It has no external Go dependencies, `replace` directives, or
runtime dependency on the lean-go repository. The checked-in package was generated
from ordinary Lean source through the installed `lean-go` CLI.

The assurance is **proved Lean logic with tested, trusted extraction**. The three
source theorems do not constitute an end-to-end proof of the generated Go program.

## Run with Go alone

From this directory:

```sh
CGO_ENABLED=0 GOTOOLCHAIN=local GOWORK=off GOPROXY=off GOSUMDB=off go test -count=1 ./...
CGO_ENABLED=0 GOTOOLCHAIN=local GOWORK=off GOPROXY=off GOSUMDB=off go run .
```

In PowerShell, set the environment first:

```powershell
$env:CGO_ENABLED = "0"
$env:GOTOOLCHAIN = "local"
$env:GOWORK = "off"
$env:GOPROXY = "off"
$env:GOSUMDB = "off"
go test -count=1 ./...
go run .
```

Expected output:

```text
clamp(7, 42) = 7
clamp(100, 42) = 42
clamp(18446744073709551615, 42) = 42
```

The Go program calls the generated typed API directly:

```go
import clamp "example.com/proved-clamp/clamp"

result, err := clamp.RunTyped(value, limit, clamp.DefaultLimits())
if err != nil {
    return err
}
```

`UInt64` becomes Go `uint64`; the maximum value remains exact. Every call starts
fresh logical resource budgets. Invalid limits return `ErrLimits`; exhausted
budgets return `ErrResource`. The executable handles errors before printing a
result. These operational errors are outside the total Lean function's theorem
statements.

## What is included

| File or directory | Purpose |
| --- | --- |
| `source/Clamp.lean`, `source/Clamp/Bounds.lean` | Ordinary Lean implementation and imported helper |
| `proof/ClampContract.lean` | Independently authored expected propositions |
| `proof/ClampProofs.lean` | Proofs of boundedness, preservation and idempotence |
| `proof-contract.json` | Selected root and theorem-to-expectation mappings |
| `clamp/` | Generated Go package and source/output manifest |
| `clamp.ir.json` | Producer IR with source and compiler provenance |
| `proof-evidence.json` | Freshly checked source proof evidence bound to generated bytes |
| `main.go`, `main_test.go`, `go.mod` | Standalone consumer, independent checks and local module |

For every `value` and `limit : UInt64`, the source claims establish:

1. `Clamp.clamp value limit ≤ limit`.
2. `value ≤ limit → Clamp.clamp value limit = value`.
3. `Clamp.clamp (Clamp.clamp value limit) limit = Clamp.clamp value limit`.

The Go tests check those properties and an independent minimum model over 169
boundary pairs and 512 seeded full-width input pairs. They also check invalid
limits, budget exhaustion and the exact executable output. These finite tests
exercise the extraction boundary; they are not proofs for all Go executions.

## Regenerate and check proofs

This development demo uses `0.1.0a5.dev0`; the published alpha.4 demo and CLI
remain on Lean 4.35.0. Install the CLI from the matching development checkout
using the repository's
[installation guide](https://github.com/franchb/lean-go/blob/main/docs/cli.md#development-checkout).
The producer requires Python **3.15**, Go **1.27.4**, and Lean/Lake **4.36.0-rc2** with
Lean commit `b35cb10cf2ced51a2fd1880cfdbf75c71ab7a35a`. Then run from this directory:

```sh
lean-go doctor
lean-go generate --source-dir source --module Clamp --root Clamp.clamp --out clamp --ir-output clamp.ir.json
lean-go check-proofs --contract proof-contract.json --manifest clamp/manifest.json --output proof-evidence.json
lean-go check-proofs --contract proof-contract.json --manifest clamp/manifest.json --evidence proof-evidence.json
```

Both proof commands rebuild and check the source proofs. `--output` writes
fresh evidence; `--evidence` verifies that the supplied evidence still matches.
The generated manifest has an empty `program.claims` list: these source claims
live in the separate proof evidence, not in a compiler-correctness certificate.

The generator accepts identical existing output and refuses differing package
bytes. After changing source or tools, use new paths such as `candidate/clamp`,
`candidate/clamp.ir.json` and `candidate/proof-evidence.json`; inspect and test the
candidate before replacing the tracked artifacts. Keep evidence outside the
source, proof and generated directories. Never edit generated Go by hand.

## Verify the complete handoff

From a lean-go checkout, with the installed CLI on `PATH`:

```sh
clamp_cli=$(command -v lean-go)
uv run --locked python scripts/check_clamp_demo.py --cli "$clamp_cli"
```

Capture the installed CLI before `uv run` adds the checkout environment to
`PATH`. In PowerShell, use `$clamp_cli = (Get-Command lean-go).Source` before
the verifier command.

The verifier copies this entire directory into a fresh external temporary
project, generates new artifacts with the installed CLI, compares every generated
file, IR and evidence byte, rechecks all three proofs, and runs the copied tests
and executable with only Go's binary directory on `PATH`. Module download and
checksum lookup are disabled, cgo is disabled, and Go caches are isolated.

Ordinary root `go test ./...` separately copies only `go.mod`, the consumer and
its tests, and generated Go sources, then tests and runs that deployment with
Go alone. No Lean sources, manifests or proof artifacts are present; nested
modules would otherwise be skipped. The installed CLI smoke
runs the complete verifier on Linux and Windows in CI. See the
[article](https://github.com/franchb/lean-go/blob/main/docs/articles/lean-proofs-to-go.md)
for the design and assurance boundary. The public
[issue tracker](https://github.com/franchb/lean-go/issues) accepts reproducible
unsupported-source and integration reports.
