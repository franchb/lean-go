# A copyable Lean-proved flag mask in Go

This standalone Go module sets, clears, toggles and tests `UInt32` flag masks.
Copy this directory anywhere and run it with Go **1.27.4** and `CGO_ENABLED=0`.
It has no external Go dependencies or `replace` directives. Lean, Python and
lean-go are needed only to regenerate the package and check the source proofs.

This example is included in the [alpha.8 candidate](../../../docs/releases/v0.1.0-alpha.8.md),
Python package `0.1.0a8`. Before publication, regenerate with the CLI from this
same [checkout](../../../docs/cli.md#development-checkout). After
publication, pair its tagged example and CLI. Published alpha.7 also has this
demo, with generator v9; use its
[tagged example](https://github.com/franchb/lean-go/tree/v0.1.0-alpha.7/examples/proofs/flags)
and [tagged guide](https://github.com/franchb/lean-go/blob/v0.1.0-alpha.7/docs/cli.md)
for historical reproduction. Current artifacts use generator v10. The checked-in
Go package needs no producer tools to run.

## Run with Go alone

From this directory:

```sh
CGO_ENABLED=0 GOTOOLCHAIN=local GOWORK=off GOPROXY=off GOSUMDB=off go test -count=1 ./...
CGO_ENABLED=0 GOTOOLCHAIN=local GOWORK=off GOPROXY=off GOSUMDB=off go run .
```

In PowerShell, set the environment first:

```powershell
$env:CGO_ENABLED = "0"
$env:GOTOOLCHAIN = "local"
$env:GOWORK = "off"
$env:GOPROXY = "off"
$env:GOSUMDB = "off"
go test -count=1 ./...
go run .
```

Expected output:

```text
set(0x00000001, 0x80000002) = 0x80000003
contains(0x80000003, 0x80000002) = true
clear(0x80000003, 0x00000002) = 0x80000001
toggle(0x80000001, 0x80000000) = 0x00000001
```

The mask selects bits directly; it is not a bit index. `contains(state, mask)`
means **all** selected bits are present, so `contains(1, 3)` is false and
`contains(state, 0)` is always true. Every 32-bit value is supported, including
the high bit `0x80000000` and the all-ones mask `0xffffffff`. There are no
input preconditions, width conversions, indexed-flag helpers or collections.

## Generated Go API

```go
import flags "example.com/lean-go-flags-demo/flags"

state, err := flags.RunSet(uint32(1), uint32(0x80000002), flags.DefaultLimits())
if err != nil {
    return err
}
allPresent, err := flags.RunContains(state, uint32(0x80000002), flags.DefaultLimits())
if err != nil {
    return err
}
fmt.Println(allPresent) // true
```

`RunSet`, `RunClear` and `RunToggle` accept `(state, mask uint32, limits Limits)`
and return `(uint32, error)`. `RunContains` has the same inputs and returns
`(bool, error)`. The generated package exports exactly these selected typed
roots; its shared raw entrypoint is `RunRoot`. The manifest sorts roots as
`Flags.clear`, `Flags.contains`, `Flags.set`, `Flags.toggle` and uses
`lean-go-manifest/v9` with the bitwise multi-root profile `pure-module/v7`.

Every call starts fresh logical resource budgets. Invalid budgets return
`ErrLimits`, exhausted budgets return `ErrResource`, and failed typed calls
return zero or false with the error. Check the error before consuming a result.
The example computes all results successfully before printing them. Budget
errors are operational behavior outside the total Lean definitions' theorems.

## Eight source claims

For **every** `state mask : UInt32`, the Lean kernel checks:

1. Setting the same mask twice equals setting it once.
2. Clearing the same mask twice equals clearing it once.
3. The cleared result AND the mask equals zero.
4. Toggling the same mask twice restores the state.
5. Setting preserves bits outside the mask.
6. Clearing preserves bits outside the mask.
7. Toggling preserves bits outside the mask.
8. The set result contains every bit selected by the mask.

Each preservation statement compares the result AND the mask's complement with
the original state AND that complement. The statements have no input assumptions.

| File or directory | Purpose |
| --- | --- |
| `source/Flags.lean` | Four ordinary pure Lean definitions |
| `proof/FlagsContract.lean` | Eight independently authored closed expected propositions |
| `proof/FlagsProofs.lean` | Source proofs, separate from the runtime source |
| `proof-contract.json` | Four selected roots and eight theorem-to-expectation mappings |
| `flags/`, `flags.ir.json` | Generated Go package, manifest and producer IR |
| `proof-evidence.json` | Deterministic source-proof evidence bound to generated bytes |
| `main.go`, `main_test.go`, `go.mod` | Standalone consumer and independent Go checks |

The assurance is **proved Lean logic with tested, trusted extraction**. The
proofs establish the source statements; they do not prove the compiler,
extractor, generated Go runtime or Go compiler correct. The runtime source does
not import the proof module. The contract does not import or reuse the proofs.
The manifest's `program.claims` list remains empty; the separate evidence records
the eight source claims and their standard axiom dependencies.

The Go tests compare all four operations against an independent per-bit arithmetic
model and check all eight laws over 144 boundary pairs, all 4,096 six-bit pairs,
and 512 seeded full-width pairs. Explicit cases distinguish all-bits containment
from any-bit containment and cover zero, high-bit and all-ones masks. Error tests
check invalid limits and exhausted budgets for all four functions, including
the absence of partial results. Finite Go tests are extraction regressions, not
universal proofs of Go executions.

## Regenerate and check proofs

Use Python **3.15** through uv, Go **1.27.4** and Lean/Lake **4.36.0-rc2** at Lean
commit `b35cb10cf2ced51a2fd1880cfdbf75c71ab7a35a`. Before alpha.8 publication,
install this checkout's CLI, replacing the example absolute path:

```sh
uv tool install --force --python 3.15 /absolute/path/to/lean-go
lean-go doctor
```

From this example directory, generate into fresh candidate paths:

```sh
lean-go generate --source-dir source --module Flags \
  --root Flags.clear --root Flags.contains --root Flags.set --root Flags.toggle \
  --out candidate/flags --ir-output candidate/flags.ir.json
lean-go check-proofs --contract proof-contract.json \
  --manifest candidate/flags/manifest.json --output candidate/proof-evidence.json
lean-go check-proofs --contract proof-contract.json \
  --manifest candidate/flags/manifest.json --evidence candidate/proof-evidence.json
```

Both proof commands rebuild and check all eight source claims. `--output` writes
fresh evidence; `--evidence` validates supplied evidence against a fresh check.
The generator refuses differing existing output and preserves it. Review and
test candidate files before replacing tracked artifacts. Never edit generated
Go, IR or evidence by hand. The [proof-contract guide](../../../docs/proof-contracts.md)
describes the trust boundary and evidence binding.

## Verify the complete handoff

From the same checkout or release tag used to install the CLI, capture its path
before `uv run` adds the checkout environment to `PATH`:

```sh
flags_cli=$(command -v lean-go)
uv run --locked python scripts/check_flags_demo.py --cli "$flags_cli"
```

In PowerShell, first use `$flags_cli = (Get-Command lean-go).Source`.

The verifier copies the example to a fresh external workspace, regenerates all
artifacts with the installed CLI, compares every generated file, IR and evidence
byte, and freshly validates the tracked evidence. It then deploys only `go.mod`
and the Go sources to another directory and runs the tests and executable with
only Go's binary directory on `PATH`, isolated caches, disabled module downloads
and checksum lookup, and cgo disabled.

Root `go test ./...` includes the same Go-only deployment on Linux and Windows.
The current checkout's installed-CLI workflow runs fresh clamp, flags, words and
bytes verification through both the direct wheel and a wheel rebuilt from the
source distribution, checking all 30 source claims per wheel and that the
installed producer payload remains unchanged. Published alpha.7 has the first
three demos; the alpha.8 candidate adds the byte codec. Before publication,
all current artifacts require this checkout's CLI.
